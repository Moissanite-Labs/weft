# Reviewing changes to weft

Moissanite Labs sorts every change into one of three lanes by the paths it touches, and reviews each lane against its
own checklist. The plan and the reasons are in
[Moissanite-Labs/siliconcordat#13](https://github.com/Moissanite-Labs/siliconcordat/issues/13).

| Lane | What | Where |
|---|---|---|
| **build** | code, CI, the site, deploys, papers and their build, program documents | this repository |
| **record** | experiment records, audits, incident write-ups | [weft-loom](https://github.com/Moissanite-Labs/weft-loom) `experiments/`, `audit/`, `incidents/` |
| **idea** | design notes, backlogs, proposals | [weft-loom](https://github.com/Moissanite-Labs/weft-loom) `notes/` |

Everything in weft is build lane. The lane check in CI (`scripts/check_lanes.py`) fails a pull request that adds a
record or a new design note here, so a reviewer should not see one. If a pull request mixes a code change with a
record, ask for the record to move to weft-loom and review the code on its own.

## Build lane checklist

A build change is ready when:

1. **It does what it says.** The description names the behaviour change and links the issue.
2. **A test covers it.** The test fails without the change. Run it, or say which CI job ran it and on which head.
3. **CI is green on the exact head.** `git status --porcelain` is empty after the tests.
4. **Every commit is signed off** (DCO), with the sign-off address equal to the author address.
5. **Claims match the code.** If a doc, the README, the site or a paper states a capability, the code path enforces
   it. A stated rule is not a checked rule.
6. **Scope is one change.** Unrelated commits or files are split out.

Request changes for a defect against this list. Leave a comment, not a blocking review, for style, naming, wording
and follow-ups.

## Papers

Papers are reviewed as build changes because their numbers are regenerated by code in CI
(`papers/*/experiments.py --check`, `scripts/build_papers.py --check`). A claim in a paper needs a passing check or a
cited record in weft-loom.

## Merging

The author does not merge their own pull request. Pull requests land through the merge queue with squash or rebase.
